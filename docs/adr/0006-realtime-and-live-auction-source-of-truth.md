# Real-time: SSE на этапе 1, WebSocket для живого аукциона; истина — состояние торгов, не видео

На этапе 1 обновления ставок и времени окончания доставляются по SSE через Redis pub/sub, с опросом как запасным вариантом. Для живого аукциона (этап 3) — WebSocket. Видеотрансляция идёт через внешний сервис стриминга (HLS с низкой задержкой; Yandex Cloud Video или Kinescope), а не через собственный WebRTC.

Задержка видео (секунды) не должна влиять на торги, поэтому источником истины считается состояние торговой сессии на сервере: текущий лот, ставки и закрытие лота приходят участникам по WebSocket независимо от видео. Модель данных хранит только идентификатор трансляции.

## Considered Options

- **Собственный WebRTC (LiveKit/mediasoup)** — отклонён: сложность и стоимость при небольшом выигрыше, если торги не зависят от видео.
- **Встраивание VK Видео / RuTube** — отклонено: чужой плеер и большая задержка.
