# Демо на GitHub Pages: тот же код на встроенной PGlite, а не ручные моки

Для показа без сервера web собирается в статический сайт (`DEMO=1`, `output: "export"`) и публикуется на GitHub Pages. Страницы рендерятся при сборке теми же запросами, что и в продакшене, но к PGlite (Postgres в WASM), куда загружен дамп с миграциями, сидом и демо-данными ([packages/db/src/demo-seed.ts](../../packages/db/src/demo-seed.ts)). Всё, чего в статике быть не может, подменяется только в демо-сборке через webpack ([apps/web/next.config.ts](../../apps/web/next.config.ts), [apps/web/demo/](../../apps/web/demo/)): клиент БД — на PGlite, сессия — на фиксированного демо-пользователя (продавец с правами администратора), Better Auth — на пустышку, модули `"use server"` — на заглушки с теми же экспортами. API-маршруты (`route.ts`) из демо-сборки исключены. Так демо не расходится с приложением: новый экран попадает в демо без отдельной работы.

## Considered Options

- **Ручные моки запросов.** Отклонено: `views` обращаются к drizzle напрямую, и моки пришлось бы писать и поддерживать для каждого запроса — второй источник правды, который быстро устаревает.
- **Обход запущенного сервера краулером.** Отклонено: нужен работающий Postgres, Redis и MinIO в CI, а клиентская навигация Next без RSC-данных превращается в полную перезагрузку страниц.

## Consequences

- Server Actions живут только в `features/*/api/actions.ts` и начинаются с `"use server"`: лоадер заглушек ищет их по этому пути. Static export не поддерживает Server Actions, и действие в другом месте сломает демо-сборку.
- Динамический маршрут объявляет `generateStaticParams` через `demoStaticParams()` из `shared/api`: в демо он перечисляет id из демо-БД, в обычной сборке возвращает `[]`.
- `searchParams` страницы читают через `readSearchParams()` из `shared/lib`: в статике параметров запроса нет, вкладки и фильтры показывают вариант по умолчанию.
- Клиентский код, который ходит на сервер (SSE, `fetch` к `/api`, Better Auth), проверяет `IS_DEMO` из `shared/config`.
- Новые демо-данные добавляются в `demo-seed.ts`. Сроки торгов отсчитываются от момента сборки, поэтому workflow пересобирает демо ежедневно.
- Отличия драйвера PGlite от postgres-js сглаживаются в [packages/db/src/demo.ts](../../packages/db/src/demo.ts): например, `db.execute()` там тоже возвращает массив строк.
