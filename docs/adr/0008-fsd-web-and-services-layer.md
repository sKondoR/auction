# Web по Feature-Sliced Design, серверные сценарии — в `packages/services`

`apps/web` построен по Feature-Sliced Design: слои `app` (маршруты Next.js, только тонкие обёртки) → `views` (страницы; называются так, чтобы не конфликтовать с pages router) → `widgets` → `features` → `entities` → `shared`. Импорты идут только вниз, соседние слайсы одного слоя друг друга не импортируют, у каждого слайса есть публичный API: `index.ts` — для UI, безопасного на клиенте, `server.ts` — для серверных запросов (`server-only`). Server actions живут в `features/*/api/actions.ts`.

Сценарии, которые затрагивают БД и нужны и web, и worker (ставка с блокировкой строки лота, финализация торгов, сделка с начислением комиссии, счета, уведомления с email-outbox, поиск), вынесены в пакет `packages/services`. Правила по-прежнему остаются чистыми функциями в `packages/domain` (ADR 0004); `services` их только применяет в транзакциях.

## Consequences

- Web и worker не дублируют сценарии: например, `finalizeLot` вызывает worker, а `placeBid` — web, при этом оба создают сделки через один `createDeal`.
- Сценарии `services` покрыты интеграционными тестами на отдельной базе `auction_test`.
- Общие компоненты без бизнес-логики (загрузчик фото, универсальная форма server action) лежат в `shared/ui`, чтобы фичи не импортировали друг друга.
