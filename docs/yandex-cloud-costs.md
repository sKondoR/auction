# Оценка стоимости Yandex Cloud и S3

Посчитал по актуальному прайсу Yandex Cloud: регион Россия, цены с НДС, новые цены действуют с 30.04.2026, месяц = 720 часов.

## Цены за единицу

| Что | Цена |
|---|---|
| **Object Storage**, стандартное хранение | 2,38 ₽ за ГБ в месяц (первый 1 ГБ бесплатно) |
| Object Storage, PUT/POST | 0,57 ₽ за 1 000 (первые 10 000 бесплатно) |
| Object Storage, GET | 0,46 ₽ за 10 000 (первые 100 000 бесплатно) |
| Object Storage, исходящий трафик | первые 100 ГБ бесплатно, дальше 1,68 ₽/ГБ |
| **CDN** | 150 ₽ в месяц, включено 150 ГБ; сверх — 1,05 ₽/ГБ. Трафик от S3 до CDN не тарифицируется |
| **Managed PostgreSQL**, Ice Lake | vCPU 100% — 1,88 ₽/ч, vCPU 50% — 1,09 ₽/ч, RAM — 0,51 ₽ за ГБ в час, SSD — 15,7 ₽ за ГБ в месяц |
| **VM (Compute)**, Ice Lake | vCPU 100% — 1,24 ₽/ч, vCPU 50% — 0,75 ₽/ч, RAM — 0,33 ₽ за ГБ в час, SSD — 14,3 ₽ за ГБ в месяц |
| **Managed Valkey (Redis)** | vCPU 50% — 1,00 ₽/ч, RAM — 0,46 ₽ за ГБ в час |
| Публичный IP | ≈ 200 ₽ в месяц |

## Сколько места займут фото

Беру в среднем 10 фото на лот. Каждое фото хранится в трёх вариантах (оригинал в WebP, средний размер, превью), всего около 0,6 МБ на фото, то есть **около 6 МБ на лот**. При 5 000 новых лотов в месяц хранилище растёт на ~30 ГБ в месяц, за год набирается ~360 ГБ. **Хранение фото — это копейки:** 500 ГБ стоят ~1 200 ₽ в месяц. Деньги уходят на трафик и на базу данных.

## Два сценария

**Старт** (до нескольких тысяч посетителей в день, без отказоустойчивости):

| Компонент | Конфигурация | ₽ в месяц |
|---|---|---|
| VM | 2 vCPU (50%), 4 ГБ, 30 ГБ SSD; на ней Next.js, cron/tick и Redis в Docker | ~2 500 |
| Публичный IP | | ~200 |
| PostgreSQL | 1 хост: 2 vCPU (50%), 4 ГБ, 20 ГБ SSD | ~3 350 |
| S3 | ~100 ГБ плюс операции | ~350 |
| CDN | до 150 ГБ трафика | 150 |
| **Итого** | | **≈ 6 500–7 500** |

**Рост** (~10 тыс. посетителей в день, база с репликой):

| Компонент | Конфигурация | ₽ в месяц |
|---|---|---|
| VM | 4 vCPU (100%), 8 ГБ | ~5 900 |
| PostgreSQL | 2 хоста s3-c2-m8 (2 vCPU, 8 ГБ) плюс SSD 50 ГБ на каждом | ~12 800 |
| Managed Valkey | 2 vCPU (50%), 4 ГБ | ~3 000 |
| S3 | ~500 ГБ | ~1 200 |
| CDN | ~1,5 ТБ | ~1 600 |
| **Итого** | | **≈ 24 000–25 000** |

**Что не входит в расчёт:**
- **SMS для входа.** У российских провайдеров это примерно 3–5 ₽ за SMS, и при хорошем трафике эта статья легко обгонит всю облачную инфраструктуру. Поэтому вход должен держать долгую сессию, а коды нужно ограничивать по частоте (rate limit).
- **Видео для живого аукциона (этап 3).** Трансляции будут крупнейшей статьёй расходов, их считаем отдельно, когда до них дойдём.
- **Балансировщик нагрузки и второй сервер приложения** для отказоустойчивости: плюс ~5–8 тыс. ₽.
- Почтовые рассылки (Yandex Cloud Postbox): копейки.

Отсюда вывод: на старте закладывай **~7–8 тыс. ₽ в месяц**, а когда пойдёт реальная нагрузка, **~25 тыс. ₽**. Самое дорогое в облаке — managed-база с репликой.

❓ **Q13** — **Конфигурация продакшна на старте.** Сценарий «Старт» (одна база без реплики, Redis в Docker на той же VM, ~7 тыс. ₽) или сразу «Рост» (~25 тыс. ₽)? У «Старта» есть риск: при сбое хоста база недоступна до восстановления, резервные копии делаются автоматически.

➡️ «Старт»: ежедневные бэкапы, восстановление на момент времени (PITR) и мониторинг. Реплику включаем, когда появится стабильный поток сделок: в Managed PostgreSQL это делается одной кнопкой, без переделки кода.
